# BitShift

Конвертер видеоархива: пережимает накопившийся материал на видеокарте, проверяет
**каждый** файл и никогда не рискует оригиналами.

Живой пример: папка с концертными съёмками ужалась со **155 ГБ до 27 ГБ**
(4K H.264 → HEVC) без видимых потерь.

**В репозитории две независимые версии:** для Windows на NVIDIA NVENC и для macOS на
Apple VideoToolbox. У них общие решения и общие правила безопасности, но ни строчки
общего кода.

Интерфейс обеих — на **русском и английском**, язык берётся из системного и
переключается внутри приложения.

## Что он делает

Показываешь ему папку — или несколько папок, или отдельные файлы — и он пережимает всё
в современный кодек, проверяет каждый результат и только после этого предлагает убрать
оригиналы.

**Битрейт считается для каждого файла отдельно** — по разрешению, частоте кадров и
исходному битрейту. Если выигрыш меньше 10%, файл не трогается вовсе: незачем гонять
кодировщик ради ничего.

**Прогноз размера виден до старта** — «155 ГБ → ~27 ГБ, −82%», без сюрпризов.

**Со звуком решаешь ты.** Многодорожечную запись можно сохранить как есть (все каналы,
исходная разрядность) или свести в стерео AAC. На 16-канальной концертной записи это
разница в размере в восемь раз.

**Сделан под медленные диски.** Если материал лежит на внешнем HDD, файлы по одному
копируются на внутренний SSD, кодируются там и переносятся обратно — иначе диск
захлёбывается от параллельных чтений. Как выяснилось, узким местом была именно эта
шина, а не видеокарта. Всё, что уже лежит на быстром диске, обрабатывается на месте.

Плюс: несколько папок за прогон, пауза и продолжение, оценка оставшегося времени
**по объёму данных**, а не по числу файлов, шкала прогресса у каждой строки и
выключение компьютера по завершении.

## Безопасность данных

Ради этого инструмент и написан. На обеих системах правила одинаковые.

- **Оригинал никогда не перезаписывается.** Результат — отдельный файл с суффиксом `_v2`.
- **Удаление только в Корзину.** Безвозвратного удаления нет нигде в обеих версиях
  и не появится.
- Оригинал убирается только после того, как результат прошёл **все четыре проверки**:
  1. результат действительно в том кодеке, который заказывали;
  2. длительность совпадает с допуском 2%;
  3. число кадров совпадает с допуском ±2;
  4. файл декодируется от начала до конца без единой ошибки.

Провалил хоть одну — оригинал остаётся ровно там, где лежал.

Проверка серьёзнее, чем кажется. Аппаратный декодер умеет терять кадры **молча** и при
этом рапортовать успехом: на реальном файле с камеры ffmpeg вышел с кодом 0, записав
результат, в котором не хватало четверти кадров, — а длительность в метаданных осталась
правильной. Ловит такое именно счётчик кадров, поэтому он и не «избыточный».

**В первый раз сними галочку автоудаления.** Посмотри на результаты своими глазами,
а Корзину доверь программе потом.

## Windows

Исходник и готовое приложение лежат в корне репозитория.

**Что нужно:** видеокарта NVIDIA (GTX 16xx и новее) — всё кодирование идёт на NVENC,
на AMD и Intel Arc приложение не запустится. Windows 10 или 11. ffmpeg в PATH:

```
winget install Gyan.FFmpeg
```

После установки закрой окно терминала, чтобы PATH обновился.

**Запуск.** Скачай `BitShift.exe` из [релизов](../../releases/latest) и запусти двойным
кликом — установки нет, это один файл. При первом запуске SmartScreen предупредит про
неизвестного издателя: **Подробнее** → **Выполнить в любом случае**.

Если не хочется доверять exe, запусти исходник напрямую:

```
powershell -STA -ExecutionPolicy Bypass -File HEVC-Converter-WPF.ps1
```

**Кодеки:**

| Кодек | Когда брать |
|---|---|
| **HEVC** | По умолчанию. Играет везде: Resolve, Premiere, телефоны, телевизоры |
| **AV1** | Примерно на 20% компактнее при том же качестве, но декодируется не везде |
| **DNxHR HQX** | Мастер под грейдинг: 4:2:2, 10 бит, intra. Считается на процессоре |

**Сборка exe** требует модуля ps2exe (`Install-Module ps2exe -Scope CurrentUser`):

```
Invoke-ps2exe -inputFile HEVC-Converter-WPF.ps1 -outputFile BitShift.exe -iconFile bitshift.ico -noConsole -STA -title BitShift -product BitShift -version 3.6.0.0
```

Исходник обязан быть сохранён в **UTF-8 с BOM**, иначе PowerShell 5.1 читает кириллицу
в строках интерфейса кракозябрами.

## macOS

Всё маковское живёт в [`mac/`](mac/), у него своя документация:
**[mac/README.ru.md](mac/README.ru.md)**.

**Что нужно:** Apple Silicon (M1 и новее) и macOS 12 или новее. В собранном приложении
уже лежат свой Python и свой ffmpeg — доустанавливать нечего.

**Запуск.** Скачай `BitShift-macOS.zip` из [релизов](../../releases/latest), распакуй и
положи `BitShift.app` куда удобно. При первом запуске macOS заблокирует приложение:
оно подписано локально, без нотаризации Apple. Два способа обойти:

- правый клик по приложению → **Открыть** → в диалоге ещё раз «Открыть»;
- либо один раз в Терминале:

```
xattr -dr com.apple.quarantine /путь/к/BitShift.app
```

После этого открывается обычным двойным кликом.

**Кодеки:** HEVC (по умолчанию, аппаратный), ProRes 422 HQ (аппаратный, с M1 Pro/Max
и старше) и AV1 (программный — аппаратного AV1-энкодера у Apple нет вовсе, поэтому он
медленный, зато очень компактный).

## Ограничения

- Windows-версия: только NVIDIA.
- Мак-версия: только Apple Silicon, и прогноз размера пока откалиброван на синтетических
  клипах, а не на большом настоящем архиве.
- Ни одна сборка не нотаризована и не подписана платным аккаунтом, поэтому обе системы
  предупреждают при первом запуске.
- Это личный инструмент, а не отполированный продукт: писался под одну конкретную задачу,
  одним человеком, проверялся на двух машинах.
