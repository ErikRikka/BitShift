# BitShift для macOS

Конвертер видеоархива для macOS. Жмёт накопившийся материал в HEVC, AV1 или ProRes
аппаратным энкодером Apple, проверяет каждый результат по четырём пунктам и только
после этого убирает оригинал в Корзину.

Окно — HTML/CSS в родном мак-окне, ядро — Python 3 поверх `ffmpeg`.

*In English → [README.md](README.md)* · *Обзор проекта → [../README.ru.md](../README.ru.md)*

---

## ⚠️ Прежде чем запускать на своих файлах

По умолчанию: кодек **HEVC**, звук — **AAC стерео**, подпапки обходятся.
Язык интерфейса — русский или английский, переключается в шестерёнке.

**Удаление оригиналов в Корзину включено по умолчанию.** Уходят только файлы,
полностью прошедшие проверку, и только в Корзину — безвозвратно не удаляется
ничего и никогда. Но если хочется просто поковыряться, **сними галочку
«Удалять исходники в Корзину после проверки»** перед первым запуском.

В командной строке наоборот: без флага `--в-корзину` ничего не удаляется.

Самый безопасный способ посмотреть, что программа собирается сделать:

```
.venv/bin/python cli.py ~/Movies/проба --режим arc --список
```

`--список` только показывает план и выходит, ничего не трогая.

> У каждого флага есть и английское имя — `--mode` то же самое, что `--режим`. Сделано
> для друзей, которым русские флаги неудобны; старые команды продолжают работать.

## Готовое приложение

Скачай `BitShift-macOS.zip` из [релизов](../../../releases/latest) — внутри уже всё:
свой Python, pywebview, PyObjC и свой `ffmpeg`. Ни Homebrew, ни окружения ставить
не нужно, только мак на Apple Silicon.

Раз внутри едет всё, едут и чужие лицензии: встроенный FFmpeg — сборка под GPL v2+.
Что это значит для собственной MIT-лицензии BitShift и полный список того, что лежит
в архиве, — в [THIRD-PARTY.ru.md](../THIRD-PARTY.ru.md).

**Первый запуск macOS заблокирует** — приложение подписано локально, без нотаризации
Apple (для неё нужен платный developer-аккаунт). Обойти можно двумя способами:

- правый клик по приложению → **Открыть** → в диалоге ещё раз «Открыть»;
- либо один раз в Терминале:

```
xattr -dr com.apple.quarantine /путь/к/BitShift.app
```

После этого запускается обычным двойным кликом.

## Сборка такого приложения

```
.venv/bin/python build.py
```

Скрипт скачивает статические `ffmpeg` и `ffprobe` под arm64 (кладёт в `build/`,
второй раз не качает), **сверяет их по SHA-256**, проверяет, что в них есть нужные
энкодеры, собирает иконку и запускает py2app. Результат — `dist/BitShift.app`,
около 128 МБ.

Дальше — про запуск из исходников, если хочется ковыряться в коде.

## Что нужно

- **мак на Apple Silicon** — используется VideoToolbox, на других системах не заработает;
- `ffmpeg` и `ffprobe`: `brew install ffmpeg`;
- Python 3.

Аппаратный ProRes есть только у M1 Pro/Max и старше. Аппаратного AV1 у Apple нет
вовсе — этот кодек считается на процессоре и потому медленный, зато компактный.

## Установка

```
cd mac
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

`.venv` в репозиторий не входит — это ~50 МБ, и он всё равно свой на каждой машине.

## Запуск

```
open BitShift.app                          # окно
./run.command                              # то же самое, если .app капризничает
.venv/bin/python app.py                    # то же самое из терминала

.venv/bin/python cli.py <папка> --режим arc --список     # план, ничего не делая
.venv/bin/python cli.py <папка1> <папка2>                # несколько папок
.venv/bin/python cli.py <папка> --звук original          # сохранить все каналы
.venv/bin/python cli.py <папка> --без-подпапок           # не заходить вглубь
```

## Тесты

Гоняют настоящий `ffmpeg` на настоящих файлах — генерируют их сами, во временной
папке. Идут небыстро: полный круг — минут двадцать, дольше всех `test_stop.py`
(около восьми минут) и `test_parallel.py`.

```
.venv/bin/python tests/test_safety.py      # гарантии: брак не стоит оригинала
.venv/bin/python tests/test_verify.py      # четыре проверки и враньё аппаратного декодера
.venv/bin/python tests/test_collision.py   # тёзки в разных папках не путаются
.venv/bin/python tests/test_audio.py       # 16-канальный звук, разбор ошибок ffmpeg
.venv/bin/python tests/test_progress.py    # оценка времени, этапы, несколько папок
.venv/bin/python tests/test_stop.py        # «Стоп» действительно останавливает
.venv/bin/python tests/test_deadlock.py    # зависание на непрочитанном stderr
.venv/bin/python tests/test_parallel.py    # стадии идут одновременно
.venv/bin/python tests/test_picker.py      # выбор источников и прогноз размера
.venv/bin/python tests/test_bundle.py      # собранный .app укомплектован
```

Дизайн окна можно крутить без единого кодирования:

```
.venv/bin/python -m http.server 8765
# открыть http://localhost:8765/tests/ui_preview.html
```

## Где что лежит

```
app.py         окно: мост между интерфейсом и ядром
cli.py         то же самое из командной строки
build.py       сборка самодостаточного .app
icon.py        пересборка иконки из ../bitshift-source.png
run.command    запуск двойным кликом из Finder
core/          ядро: вся логика, про интерфейс ничего не знает
  config.py      все настраиваемые числа, пути и строки — в одном месте
  pipeline.py    конвейер — стадии идут одновременно
  encode.py      сборка и запуск ffmpeg, разбор его ругани
  verify.py      четыре проверки результата
  modes.py       режимы, расчёт битрейта, отсев
  estimate.py    прогноз размера до старта
  staging.py     кэш на быстром диске
  probe.py       ffprobe: что за файл
  eta.py         сколько осталось — по байтам, не по файлам
  lang.py        строки интерфейса на двух языках
  trash.py       Корзина через системный API
ui/            интерфейс: обычные HTML, CSS и JS
tests/         проверки
BitShift.app   лёгкая обёртка: своего Python нет, зовёт соседний app.py
```

**`BitShift.app` в этой папке нельзя переносить отдельно от проекта** — он ссылается на
соседние `.venv` и `app.py`. В Dock можно, но сам бандл должен остаться на месте.
Самодостаточный вариант — тот, что собирается в `dist/`.

## Если хочется покрутить параметры

Всё настраиваемое лежит в `core/config.py`: допуски проверки, доли шкал, размер запаса
на диске, сколько потоков, отсрочка выключения, размеры окна. В самих модулях значений
нет — менять нужно только там.

Комментариев в коде нет намеренно. Почему всё сделано именно так — в `CLAUDE.md`.
