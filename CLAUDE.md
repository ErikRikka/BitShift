# CLAUDE.md — BitShift для Windows

Гайд для Claude Code по этому проекту. Читай целиком перед любыми правками.

> **В репозитории две независимые версии.** Этот файл — про **Windows** (PowerShell + WPF,
> NVENC). Мак-версия живёт в `mac/` (Python + HTML, VideoToolbox), у неё свой
> `mac/CLAUDE.md` — общего кода нет ни строки, правки сюда её не касаются.
> Что переносить с Windows на мак — в `docs-mac-port.md`.

## 1. Что это

Персональный GPU-конвертер видео для Windows под режиссёра-любителя. Пережимает
видео в **AV1 / HEVC / DNxHR** через видеокарту (NVIDIA NVENC/NVDEC) с обязательной
проверкой целостности результата и безопасным удалением исходников только в Корзину.

Не продукт для раздачи, а инструмент под одного пользователя. Приоритеты: **меньше
места на дисках, без потери качества, без риска потерять исходники.**

## 2. Файлы и точки входа

Папка проекта: корень этого репозитория.

| Файл | Роль |
|------|------|
| **HEVC-Converter-WPF.ps1** | ГЛАВНЫЙ код приложения (WPF, тёмный UI). Это релиз. Правим его. |
| **Конвертер HEVC.exe** | Собран из WPF.ps1 через ps2exe. То, по чему пользователь кликает. После правок WPF.ps1 **пересобирать exe**. |
| **Конвертер HEVC GUI.vbs** | Запуск WPF.ps1 без чёрного окна консоли (`-STA -WindowStyle Hidden`). Запасной вход, если exe заблокирует SmartScreen. |
| HEVC-Converter-GUI.ps1 | СТАРАЯ WinForms-версия. Запасная, deprecated. Не трогаем без нужды. |
| HEVC-Converter-v1.ps1 + Конвертер HEVC.bat | Консольный вариант (интерактивный, только HEVC). Отдельная альтернатива. |
| КАК УСТАНОВИТЬ.txt | Инструкция для пользователя (установка ffmpeg, запуск). |

**Приложение называется BitShift** (с v2.8). Основной файл — `BitShift.exe`, иконка
`bitshift.ico` (тёмная плитка, зелёное кольцо, красный сегментированный круг — мотив
из картинки пользователя; на размерах <24px разрезы не рисуются, иначе каша). Тот же
знак нарисован шейпами в рейле рядом с названием. Старый `Конвертер HEVC.exe` — удалить,
он устарел.

Актуальная версия exe: **v3.6**.

**Как нумеруем версии** (правило пользователя): средняя цифра — за обычную порцию
правок, какой бы длинной ни была сессия (вся эта пачка изменений = один шаг 3.5 → 3.6,
а не 3.6/3.7/3.8). Мелочь вроде новой иконки или одной подписи — третья цифра: 3.6.1.
Не разгонять номер версии по ходу работы.

Новое в v3.6 (одна сессия правок по живым скриншотам; расположение шестерёнки выбирали
по рендерам семи вариантов, место галочки подпапок — по четырём):

- **Версия приложения видна в карточке настроек** (`$APP_VERSION` — единственное
  место, где живёт номер; `LblVersion` внизу попапа под чертой). При сборке exe
  передавать ps2exe тот же номер, иначе разъедется.
- **Шестерёнка переехала в правый нижний угол рейла** (`HorizontalAlignment="Right"`,
  у попапа `HorizontalOffset="4"`). Слева она висела ни к чему не привязанная.
- **«Включая подпапки» — из рейла в шапку главной панели**, рядом с «Обзор…», и
  **включена по умолчанию**. Это область выбора («что берём»), а не настройка сжатия,
  поэтому место рядом с выбором папки. Контрол теперь `ToggleButton` со стилем `Toggle`
  (выключенный неотличим от «Обзор…», включённый — акцентная заливка `#33203A` +
  кромка `#8E1A58`): состояние видно с одного взгляда, чего галочка в углу не давала.
  **Не забыть:** контрол добавлен в список `SetIsHitTestVisibleInChrome`, иначе клики
  по нему таскали бы окно (он попадает в `CaptionHeight=34`).
- **Звук по умолчанию — AAC-стерео** (`$script:AudioSel = 1`, `IsChecked` у `Audio1`).
  Причина та же, что и в v2.9: разница по размеру огромна (12 ГБ против 1,5 ГБ на
  концертном файле), а многоканальный PCM ещё и роняет встроенный AAC-энкодер.
  Копия оригинальной дорожки осталась одним кликом рядом.
- **Один диалог на всё, и в нём можно набрать НЕСКОЛЬКО папок.** «Обзор…» открывает
  системный `IFileOpenDialog` в обычном файловом режиме (видно и папки, и видеофайлы,
  файлы берутся мультивыбором), а в него через `IFileDialogCustomize` **дорисована
  кнопка «Добавить эту папку»** — она кладёт текущую папку в список, не закрывая окно.
  Класс — `MixedPicker` (заменил `MultiFolderPicker`, тот удалён); кнопку ловит сник,
  реализующий `IFileDialogEvents` + `IFileDialogControlEvents`, `OnButtonClicked` берёт
  `GetFolder()`. **Порядок методов в объявлениях интерфейсов = порядок vtable, менять
  нельзя.** Папки засчитываются и при закрытии по «Отмене» — их добавили явным нажатием.
  Если класс не соберётся, есть `Browse-Fallback` (файлы + одна папка через заглушку).
  Отдельную кнопку «Файлы…» пробовали и убрали: пользователь хочет один диалог.
- **Пробой (см. §9) выяснено, почему вариант с заглушкой в поле имени плох:** диалог
  дописывает к имени расширение из фильтра (`(вся эта папка)` → `(вся эта папка).mp4`,
  отсюда `AddExtension = $false` и сравнение без расширения), а две настоящие папки
  в поле имени он не возвращает вовсе — уходит в навигацию.
- **Состояние выбора: `$script:ScanDirs` (папки целиком) + `$script:PickedFiles`
  (поштучные файлы).** Корнями (`BaseDirs`) становятся и те, и папки выбранных файлов —
  поэтому SSD-кэш, лог и имена строк работают как раньше. `Refresh-FileList` для корня
  из `ScanDirs` сканирует папку, для остальных берёт только выбранные файлы. Смешанный
  выбор поддержан (папка B целиком + два файла из A — проверено). `Set-Selection` —
  общий вход, `Set-Roots` теперь тонкая обёртка над ним (её зовут тест-хуки).
  Переключатель подпапок гаснет, когда выбраны ТОЛЬКО файлы (`FilesOnlyMode`).
- Фильтр диалога — расширения ВСЕХ режимов, иначе нужный файл просто не был бы виден.
  Файл, не подходящий текущему режиму, показывается отдельной строкой «не для этого
  режима» (`Kind='skip'`, залочена), а не исчезает молча.
- **Шапка главной панели разведена по колонкам** (`*` + `Auto`, заголовок с
  `TextTrimming`). Раньше заголовок и кнопки лежали в одном `Grid` внахлёст — с более
  широкой правой группой пилюля наезжала на название режима.
- **Окно 1035×700** вместо 900×700 (+15% по просьбе), минимум поднят 820 → **900**
  (на 820 длинное имя режима ужималось в многоточие). На минимуме «Старое видео
  (AVI, WMV, MTS)» всё равно обрезается — если мешает, лечится коротким «Подпапки».
- **Мини-шкала в строке тянется по ширине окна.** Была фиксированная (`Width="300"`,
  `$ROWBAR_W`, ширина заливки в пикселях) — на широком окне выглядела огрызком.
  Стало: `FileRow.BarPct` (доля 0..100) плюс `BarFillLen`/`BarRestLen` — это
  `GridLength` со звёздочкой, разметка делит трек двумя колонками. Из-за `GridLength`
  в `Add-Type` добавлены `PresentationFramework` и `using System.Windows;`.
  Конвертеров в проекте нет (негде их регистрировать), звёздочные колонки — способ
  получить проценты чистой разметкой. `Set-RowBar` теперь кладёт долю как есть.
- **Кнопка «Удалить проверенные…» вровень со «Стартом»**: 38px, шрифт 13.5. Была 32.6 —
  «Старт», «Пауза» и «Стоп» лежат в одном `StackPanel` и тянутся по самому высокому,
  а кнопка удаления жила в своём и оставалась по размеру контента. Лечится не жёсткой
  высотой, а `VerticalAlignment="Stretch"` (жёсткая разъедется при масштабе шрифта).

Новое в v3.5: **шестерёнка настроек** внизу рейла
(`BtnGear` + `PopSettings`, WPF Popup со `StaysOpen=False`, `AllowsTransparency`,
`PlacementTarget` задаётся из кода — надёжнее биндинга по имени). В попап переехали
выбор языка, «Удалять исходники в Корзину» и «Выключить компьютер» — главная панель
разгрузилась, справа внизу осталась только кнопка удаления.

Значок шестерни — **сплошной силуэт** (`Path` с `Data`, зубцы трапециями, отверстие
через `F0` = EvenOdd прямо в разметке пути). Две грабли: у `Path` **нет свойства
`FillRule`** (оно у геометрии, поэтому префикс `F0`), и координаты надо форматировать
через `InvariantCulture` — иначе русская культура пишет `14,89` вместо `14.89` и XAML
рассыпается. Вариант со штрихами (кольцо + 8 лучей) на 18px читался как солнце, поэтому
и перешли на силуэт.

Счётчик в кнопке удаления вынесен в скобки — `Удалить проверенные (5) в Корзину…`,
чтобы не согласовывать падеж с числом.

**Грабля, повторившаяся дважды: в PowerShell имена переменных регистронезависимы.**
Сначала `$w` затирал `$W` в скрипте иконки, потом `foreach ($lang in …)` в тесте затирал
`$script:Lang` — из-за чего `Set-Lang` считала язык уже установленным и молча выходила.
Не называть локальные переменные так же, как поля состояния.

Версия v3.1. Новое в v3.1: **кодек по умолчанию — HEVC**
(`$script:CodecSel = 1`; причина: у M1/M2 нет аппаратного декода AV1 — он появился
только с M3, а пользователь планирует смотреть архив с макбука). Подписи кодеков —

в блоке «ОБЪЁМ»: `Estimate-Row` считает по той же формуле, что и `Prep-Item`, включая

снятие галочки отражается сразу. `Reset-Estimate` — при смене звука (смена режима или
кодека и так вызывает `Refresh-FileList`). **`$EST_OVERHEAD = 1.15`** — эмпирическая
поправка: NVENC стабильно отдаёт больше заданного `-b:v` плюс накладные расходы
контейнера; без неё прогноз занижался на 14%, с ней расхождение с фактом 1,2%
(замерено). Для DNxHR прогноз не считается — битрейт задаёт профиль.

**Иконка `bitshift.ico` — из картинки пользователя `bitshift-source.png`** (тёмная
плитка, розово-фиолетовая девятка). Картинка сама по себе не перерисовывается, но
**кадрируется по плитке** (пользователь попросил, чтобы девятку было лучше видно):
в исходнике плитка занимает 51% кадра, кроп убирает поля. Границы плитки ищутся
по РЕЗКОМУ ПЕРЕПАДУ яркости на её краю (по яркости она с фоном не контрастирует —
у кадра свой градиент), причём линии замера берутся в стороне от девятки, иначе её
контрастный край перебивает край плитки. **Грабля: в PowerShell имена переменных
регистронезависимы — `$w` затирает `$W` (ширину картинки)**, из-за этого кроп молча
ужимался; размеры плитки держать в `$tw/$th`. Логотип в рейле — та же кропнутая
картинка, 96px PNG в base64 внутри `$script:LogoB64` (иначе exe зависел бы от
внешнего файла); скрипт-генератор вшивает base64 сам, заменяя плейсхолдер. Пересобирать ico из PNG скриптом (GDI+ → BMP-формат,
8 размеров). **Осторожно: если положить PNG под именем .ico, ps2exe падает с
`CS1567: Error reading icon … data is invalid` и УДАЛЯЕТ старый exe** — так уже было.
Акцент интерфейса взят пипеткой из этой картинки: розовый `#DB1671`, фиолетовый
`#6E4A9E`, кромка `#FF8FCB`. Знак в рейле — та же девятка (два Ellipse + Path-хвост).
Прежний зелёно-красный «арбуз» больше не используется.

Новое в v2.9: секция **ЗВУК** в рейле —
«Оригинал · все каналы» (`-c:a copy`, по умолчанию) или «AAC стерео · компактно»
(`-c:a aac -b:a 256k -ac 2`). Повод: 16-канальная многодорожка с концерта

не умеет >8 каналов («Unsupported channel layout 9.1.6»). Именно `-ac 2` снимает
ограничение. Разница по размеру огромна: тот файл — 12 ГБ с копией звука против
1,5 ГБ со стерео. Если звук не лёг в контейнер, есть однократный откат на AAC
(`$item.AudioForce`). `ErrSummary` теперь достаёт из stderr настоящую ошибку, а не
первое предупреждение (раньше в статусе висело безобидное «Guessed Channel Layout»).
Рейл от новой секции переполнялся — уплотнены отступы (Nav padding 14,7; заголовки
секций 0,16,0,5), окно 700/минимум 672. Новое в v2.8: имя BitShift + иконка + знак в рейле;
блок «ОСТАЛОСЬ» под «ОБЪЁМ» — оценка времени по БАЙТАМ (`Update-Eta`, `HumanTime`),
не по числу файлов (у пользователя в одной папке и 100 МБ, и 9 ГБ — счёт по штукам
врал бы в разы), со сглаживанием 0.75/0.25 и порогом 20 с перед первой оценкой;
**решение о кэшировании принимается ПОФАЙЛОВО** — `IsSlowPath` (мемоизация по корню
пути в `$script:SlowCache`), файл на внутреннем SSD кодируется на месте без копирования
в TEMP. Раньше при мультивыборе хватало одной USB-папки, чтобы гнать через кэш вообще
всё. Новое в v2.7: выбор НЕСКОЛЬКИХ папок
сразу (Ctrl/Shift, `MultiFolderPicker` через IFileOpenDialog; список — `$script:BaseDirs`,
пустой = работаем по `$script:BaseDir`, так живут тест-хуки); шкала прогресса в каждой
строке под именем файла (тогда `FileRow.BarWidth`, 300px; с v3.6 это `BarPct` и
тянущиеся колонки, см. выше) на всех

## 4. ЖЕЛЕЗНЫЕ ГАРАНТИИ БЕЗОПАСНОСТИ (НЕ ОСЛАБЛЯТЬ)

Это ядро доверия к инструменту. Пользователь сам отмечал их как неприкосновенные.
Любое изменение, касающееся удаления/перезаписи — сначала проговорить с пользователем.

- **Оригинал никогда не перезаписывается.** Результат — отдельный файл с суффиксом `_v2`.
- **Удаление — ТОЛЬКО в Корзину** (`Microsoft.VisualBasic.FileIO.FileSystem.DeleteFile`
  … `SendToRecycleBin`), **никогда безвозвратно.** Безвозвратное удаление я делать
  отказываюсь даже по прямой просьбе — только в Корзину.
- Удаляются **только файлы, полностью прошедшие проверку** (список `$script:GoodSrc`).
- **Проверка каждой пары** (оригинал+результат): результат нужного кодека
  (`hevc`/`av1`/`dnxhd`) + длительность ±2%/2с + число видеокадров ±2 (`ffprobe
  -count_packets`, только для mp4/mov) + **полное декодирование** результата
  (`-hwaccel cuda`, при ошибках перепроверка на CPU).
- **Автоудаление** (галочка «Удалять исходники в Корзину после проверки») — с v2.7
  **по умолчанию ВКЛ** (пользователь попросил явно, 2026-07-21). Тоже только в Корзину,
  тоже только `GoodSrc` (поштучно; провалившие проверку — исходник остаётся).
  Само правило «только в Корзину и только после полной проверки» — не ослаблять.
- Пользователь **быстро чистит Корзину** → страховочная сетка тонкая, брак надо ловить
  проверкой ДО удаления, а не надеяться на восстановление.

## 5. КРИТИЧЕСКИЕ ПОДВОДНЫЕ КАМНИ (выстрадано)

- **UTF-8 С BOM обязателен** для всех .ps1 (иначе PS 5.1 читает кириллицу кракозябрами).
  После любой правки .ps1 пересохранять с BOM:
  `$t=[IO.File]::ReadAllText($f); [IO.File]::WriteAllText($f,$t,(New-Object System.Text.UTF8Encoding $true))`.
  **Нельзя PS7-синтаксис** (тернарник, `??`) — целевая версия 5.1.
- **После каждого `Start-Process -PassThru` нужно `$null = $proc.Handle`**, иначе
  `.ExitCode` после завершения возвращает `$null`, и успешные операции считаются
  ошибками. Это касается ffmpeg и robocopy.
- **NVDEC декодирует аппаратно только 8-бит 4:2:0 H.264/HEVC.** На 4:2:2/10-бит
  (Sony XAVC) `-hwaccel cuda` НЕ падает, а молча теряет ~9 первых кадров GOP.
  Поэтому: `h264` с `pix_fmt != yuv420p/yuvj420p` → декодируем на CPU (без `-hwaccel`);
  DNxHR всегда на CPU. Проверка числа кадров — сетка, ловящая такой брак.
- **И av1_nvenc, и hevc_nvenc на RTX 4070 роняют 4:2:2 → 4:2:0** (4:2:2 в NVENC только
  с RTX 50). Полный цвет 4:2:2 сохраняет только DNxHR (intra, CPU).
- **`-hwaccel_output_format cuda`** (весь путь decode→encode в VRAM, +~15%) — только для
  надёжного пути: 8-бит 4:2:0 `h264`/`hevc`. Для 10-бит и не-GPU (DNxHR) не применять.
- **Без `-movflags +faststart`** — он в конце переписывает весь файл; на USB-диске это
  секунды 100% загрузки диска при простаивающем энкодере.
- **JOBS=3** — замеренный пик агрегатной пропускной (4-5 хуже). Пресет **p5** (за него
  обрыв скорости вдвое). AV1 = та же скорость что HEVC, но ~20% меньше при равном
  качестве (замерено по VMAF).
- **NVENC и NVDEC — разные блоки кремния** → проверка (NVDEC) идёт параллельно
  кодированию (NVENC), NVDEC при энкоде загружен лишь ~наполовину.
- **SSD-кэш обязан класть каждый файл в СВОЮ подпапку в %TEMP%** (не в плоский TEMP по
  basename). Камера сбрасывает нумерацию на каждой карте → в подпапках-«городах» полно
  файлов с одинаковым basename (C0008 сразу в трёх папках-съёмках). Плоский TEMP их
  сталкивал: два-три ffmpeg писали в один `C0008_v2.mp4`, гонка обходила проверку, и в
  папку-город переносился ЧУЖОЙ результат, а оригинал уходил в Корзину. Это уже привело к
  порче 11 мастеров (восстановлены из Корзины). Фикс v2.5: `StageDir` =
  `%TEMP%\<random>\` на каждый файл, имена больше не пересекаются. НЕ ослаблять.

## 6. Архитектура WPF-приложения (HEVC-Converter-WPF.ps1)

- **XAML** в here-string, грузится `[System.Windows.Markup.XamlReader]::Load(([xml]$xaml))`.
  XAML обязан быть **валидным XML** — следить за парностью тегов, особенно вложенные
  `Border` в `ControlTemplate` (там уже ловили незакрытые/дублированные теги).
- **Строки списка — C#-класс `FileRow`** (`INotifyPropertyChanged`, через
  `Add-Type -ReferencedAssemblies PresentationCore,WindowsBase,System.Xaml`): свойства
  `Name, Info, Size, Status, StatusColor(Brush), IsChecked, CanCheck, Tag,
  BarPct/BarFillLen/BarRestLen (мини-шкала долей), BarColor`. Список сам
  обновляется при смене свойства. `$script:Rows` = `ObservableCollection[object]` →
  `$Lv.ItemsSource`. `Set-ItemStatus $row $text $brush` меняет Status/StatusColor.
- **Режимы/кодек** — данные (`$Modes`, `$Codecs`), выбор в `$script:ModeSel`/`$script:CodecSel`,
  `CurrentMode`/`CurrentCodec` читают их. В UI — RadioButton'ы (GroupName), стилизованы
  под пилюли, `Add_Checked` -> обновляет ModeSel/CodecSel + `Refresh-FileList`.
- **Прогресс-бар** — родной WPF `ProgressBar` со стилем (`PART_Indicator`), `$Bar.Value/.Maximum`
  работают нативно (обёртка не нужна, в отличие от WinForms-версии).
- **Безрамочное окно**: `WindowStyle="None"` + `WindowChrome` (CaptionHeight=34 для
  перетаскивания, ResizeBorderThickness=6), свои кнопки свернуть/закрыть (BtnMin/BtnClose,
  `WindowChrome::SetIsHitTestVisibleInChrome`), скругление углов — `DwmSetWindowAttribute($h, 33, 2)`
  в `Add_SourceInitialized`.
- **Опрос конвейера** — `DispatcherTimer` (400 мс) -> `Step-Pipeline`, только в фазе `'run'`.
- Диалоги: `[System.Windows.MessageBox]`, папка — `System.Windows.Forms.FolderBrowserDialog`.
- `Set-ControlsEnabled` гасит рейл/кнопки на время работы, **но НЕ список** (отключённый
  ListBox светлеет; плюс прокрутка во время работы полезна).

## 7. Режимы и кодеки

**Режимы** (`$Modes`, поля Kind/Ratio/Floor/BppMin/BppMax/Ext/Name):
1. `old` «Старые ролики»: .avi/.wmv/.mts → .mp4; 55% [пол 1.5 Мбит/с … 0.15 bpp].
2. `cam` «Съёмка S-Log3»: .mp4/.mov; 45% [0.10 … 0.20 bpp]; сохраняет 10 бит и цвет.
3. `cam` «Исходники шоу»: .mp4/.mov; 60% [0.08 … 0.10 bpp].
4. `arc` «Домашний архив / Reels»: .mp4/.mov; фикс `ARC_BPP=0.096`; уже компактное
   (bpp ≤ цель×1.12) и уже-HEVC отсеиваются.
Битрейт = доля от исходного, зажатая рамками бит/пиксель, но не ниже пола. Выигрыш <10% → пропуск.

**Кодеки** (`$Codecs`, поля Key/Enc/OutCodec/Gpu/Compress/Container/Tag/Profile):
- `av1` (av1_nvenc, .mp4) — самый компактный (~−20% к HEVC), по умолчанию. Нужен
  Resolve Studio / современный плеер.
- `hevc` (hevc_nvenc, контейнер как у источника, тег hvc1) — максимально совместимый.
- `dnxhr` (dnxhd, dnxhr_hqx, .mov) — грейдинг-мастер: intra, 4:2:2 10 бит, CPU-кодек+декод,
  крупный, без битрейт-логики.

## 8. Конвейер (единая фаза 'run', совмещённые кодирование+проверка+перенос)

`Step-Pipeline` каждый тик вызывает `Step-Encode` + `Step-Verify` + `Step-Move`:
- **Step-Encode**: до `JOBS=3` параллельных ffmpeg. Готовый файл сразу в `$script:VQueue`
  (проверка стартует параллельно). Инфо о результате пишется в `$row.Info`
  («→ av1 · 45 МБ · −89%»).
- **Step-Verify**: во время кодирования лимит `VJOBS_OVERLAP=2` (чтобы декод проверки не
  отбирал NVDEC у энкодера), после — полный `VJOBS=4`.
- **Step-Move**: staged-результаты (SSD-кэш) переносятся обратно на USB, только когда
  `Encoding-Active` = false (USB свободен от копирования исходников).
- Готовые пары прошлых запусков (`$script:DeferredPairs`) выпускаются на проверку в конце.
- `Finish-Run` когда всё дренировано; при включённой галочке — `Recycle-Good 'авто'`.

**SSD-кэш** (`IsSlowDrive`: BusType=USB через Get-Partition/Get-Disk, либо
`$env:HEVC_WPF_FORCESTAGE='1'`): при USB-источнике файлы по одному копируются robocopy'ем
в `%TEMP%`, кодируются/проверяются на NVMe, результаты переносятся обратно — чтобы USB-диск
не толкался параллельными чтениями (это было главным узким местом, не GPU).

Именование результата: `_v2` (напр. `00001_v2.mp4`). Файлы, чьё имя оканчивается на `_v2`,
из кандидатов исключаются. Рекурсия по подпапкам — галочка «Включая подпапки» (по умолч.
выкл), имя строки = путь относительно выбранной папки; результат кладётся рядом с исходником.

## 9. Как тестировать (я работаю ВСЛЕПУЮ — окно вживую не вижу)

**Всегда** после правки: пересохранить с BOM + распарсить
(`[System.Management.Automation.Language.Parser]::ParseFile`).

- **Headless-прогон конвейера** (окно не показывается):
  ```
  $env:HEVC_WPF_TEST='1'
  . '...\HEVC-Converter-WPF.ps1'
  $script:BaseDir=$dir; $script:ModeSel=2; $script:CodecSel=0
  Refresh-FileList; Start-Run
  while ($script:Phase -ne 'done') { Step-Pipeline; Start-Sleep -Milliseconds 200 }
  ```
  Проверять `$script:Counts` (ok/skip/err/vgood/vbad), `$script:Rows[].Info/.Status`,
  наличие `_v2`-файлов через ffprobe. Staged-режим: `$env:HEVC_WPF_FORCESTAGE='1'`.
- **Рендер UI в PNG** (визуальная проверка вслепую):
  ```
  $root=$Window.Content; $Window.Content=$null
  $root.Measure((New-Object System.Windows.Size(900,636)))
  $root.Arrange((New-Object System.Windows.Rect(0,0,900,636))); $root.UpdateLayout()
  $rtb=New-Object System.Windows.Media.Imaging.RenderTargetBitmap(900,636,96,96,[System.Windows.Media.PixelFormats]::Pbgra32)
  $rtb.Render($root)
  $enc=New-Object System.Windows.Media.Imaging.PngBitmapEncoder
  $enc.Frames.Add([System.Windows.Media.Imaging.BitmapFrame]::Create([System.Windows.Media.Imaging.BitmapSource]$rtb))
  $fs=[IO.File]::Create($png); $enc.Save($fs); $fs.Close()
  ```
  Каст `[BitmapSource]$rtb` обязателен (иначе ambiguous overload). `Show()`+pump НЕ измеряет
  окно (ActualWidth=0) — нужен detach+Measure/Arrange. **В рендер НЕ попадают** живые
  DWM-эффекты (скругление углов окна, безрамочность, hover-анимации) — их подтверждает
  пользователь скриншотом.
- **Системные диалоги ТОЖЕ проверяются вслепую — сообщениями, а не клавиатурой.**
  Открываем диалог из своего же процесса, а из `System.Windows.Forms.Timer` (его WM_TIMER
  доезжает и внутри модального цикла диалога) находим окно: `EnumWindows` → своё PID +
  класс `#32770`. Дальше `EnumChildWindows` даёт кнопки (класс `Button`, `GetDlgCtrlID`:
  1 = OK, 2 = Отмена, дорисованные — по тексту) и поле имени (единственный видимый `Edit`).
  Жмём `BM_CLICK` (0x00F5), текст кладём `WM_SETTEXT` (0x000C), читаем `WM_GETTEXT` (0x000D).
  **Так проверено, что кнопка «Добавить эту папку» появляется и папка возвращается.**
  `SendKeys` НЕ использовать: диалог не всегда получает фокус, и клавиши уедут
  в чужое окно. Запускать пробу с внешним таймаутом и закрывать диалог самим
  (клик по id 2), иначе окно повиснет.
- **Пересборка exe** (после правок WPF.ps1):
  ```
  Import-Module ps2exe
  Invoke-ps2exe -inputFile '...\HEVC-Converter-WPF.ps1' -outputFile '...\Конвертер HEVC.exe' -noConsole -STA -title 'Конвертер HEVC' -product 'Конвертер HEVC' -version 'X.Y.0.0'
  ```
  Смоук-тест: запустить exe с `$env:HEVC_WPF_TEST='1'`, ждать код выхода 0.
- Тестовые видео генерирую `ffmpeg -f lavfi -i testsrc2=...`. Прибираю за собой временные
  файлы (в скретчпад-директории, не в проект). Тест-хуки `HEVC_WPF_TEST`/`HEVC_WPF_FORCESTAGE`
  в проде инертны — не удалять, через них вся проверка.

## 11. Быстрый чек-лист правки WPF.ps1

1. Внести изменение.
2. Пересохранить файл с UTF-8 **BOM**.
3. Распарсить (`Parser::ParseFile`) — 0 ошибок.

7. Прибрать временные файлы. Отчитаться, попросить скриншот если менял вид.
8. Не менять архитектуру и не переписывать рабочий код без явной просьбы.
